# Modding WarioBlast Recomp

Mod packs can replace the game's graphics with high-resolution art (tiles,
sprites, backgrounds, the Super Game Boy border) and replace its music and
sound effects. Several packs can be active at once.

> **Share original work only.** The dump tool (below) extracts the game's own
> graphics and sound from *your* ROM so you can see what to redraw. Those
> files are Nintendo's; keep them private. A pack you publish should contain
> only art and audio you made.

## Installing and enabling packs

Put each pack in its own folder inside `mods/` next to the executable:

```
warioblast.exe
mods/
  MyHDPack/
    pack.ini
    tiles/ ...
```

Enable packs in the launcher under **MOD PACKS → MANAGE...**. Enter/A turns
a pack on or off, and ←/→ changes its priority. When two packs replace the
same thing, the one higher in the list wins. From the command line use
`--mod NAME` (repeatable, highest priority first), `--mods-dir DIR` or
`--no-mods`. In game, **F9** turns mods off and on to compare.

## Example pack

`examples/mods/WarioBlast-Example` (also in `mods/` in the release downloads)
shows each part of the format:

- `border/border.png`: an HD Super Game Boy border at scale 4 (1024 × 896)
  with a transparent centre;
- `tiles/`: HD versions of the status-bar digits 0–9 (stage timer, enemy
  count), drawn with the four greys (`color = indexed`), so they take on
  the game's SGB colours;
- `audio/music_0b.ogg` + `music_0b.ini`: a new tune for the first stage,
  with a one-bar intro and a `loop_start` after it.

Everything in it is original and generated by `tools/make_example_pack.py`,
which rebuilds the pack and is a readable reference for the format.

## Making a pack

1. **Dump.** Turn on *DUMP FOR MODDING* in the mods screen (or run with
   `--dump DIR`, plus `--dump-audio` to also record each song), then play
   through the parts you want to change. You get, in `mods/_dump/`:
   - `tiles/<key>.png`: every tile the game drew, 8×8, as editable colour
     indices (white = colour 0, transparent; light grey = 1; dark grey = 2;
     black = 3);
   - `tiles_seen/<key>_<palette>[_sprite].png`: the same tiles as they looked
     on screen with each palette, for reference;
   - `border/border.png` and `border/<key>.png`: the SGB border;
   - `audio_log.txt`: every music / sound-effect request with its frame;
     `audio/music_<id>_original.wav` with `--dump-audio`;
   - `pack.ini`: a template with the palettes the game used most.
2. **Redraw** the tiles you want at a larger size, keeping the file names.
3. **Copy** your files and the `pack.ini` into `mods/<YourPack>/` and enable it.

## pack.ini

```ini
name = My HD pack
author = Your name
version = 1.0
description = One line shown in the launcher
scale = 4          ; the size your art is drawn at (tiles are 8*scale pixels)
color = rgba       ; or indexed (see below)
ref_bgp = E4       ; palettes your rgba art was drawn for (from the dump's template)
ref_obp0 = E4
ref_obp1 = E4
```

## Graphics

### Tiles: `tiles/`

| File | Used for |
|---|---|
| `<32 hex digits>.png` | that tile, with any palette |
| `<32 hex digits>_<2 hex digits>.png` | that tile only when drawn with that palette value (BGP/OBP0/OBP1), e.g. a different look while flashing |

The 32 hex digits are the tile's 16 bytes of Game Boy pixel data; copy them
from the dump's file names. Images must be square, 8 × scale pixels (scale
1–16). Packs may use different scales; the game is drawn at the largest one.

Replacement art is used everywhere that tile appears: in the background, in
the window (status bar) and in sprites, including flipped sprites.
Transparent pixels show the background behind sprites. On background tiles
they show colour 0. Sprite art may be drawn outside the original sprite
silhouette, as long as it stays inside the tile.

### Colour modes

- **`color = rgba`** (default): your art's colours are used as drawn. The
  game fades by changing palettes, so when the palette differs from the
  `ref_*` palettes in `pack.ini`, the art is shifted by the same colour
  difference, and fades to white or black still work.
- **`color = indexed`**: draw with the four greys (white, light, dark, black).
  They are colour indices, so the game's real palettes and SGB colours apply
  exactly, including fades. Good for higher-resolution art in the original
  style. For sprites, white is transparent.

### SGB border: `border/`

- `border/border.png`: the whole border, 256 × 224 times the scale. The
  game shows through transparent pixels (the centre should be transparent).
- or `border/<64 hex digits>.png`: individual 8×8 border tiles at your scale,
  named from the dump.

## Audio: `audio/`

| File | Replaces |
|---|---|
| `music_<id>.ogg` / `.wav` | song `<id>` (2 hex digits, see `audio_log.txt`) |
| `sfx_<id>.ogg` / `.wav` | sound effect `<id>` |
| `sgb_score_<id>`, `sgb_a_<id>`, `sgb_b_<id>` | Super Game Boy SNES-side music / effects (needs the SGB BIOS) |

OGG Vorbis or WAV (8/16-bit PCM or 32-bit float), any sample rate, mono or
stereo. Music loops by default; to set a loop region add
`music_<id>.ini` with `loop_start = <sample>` and/or `loop_end = <sample>`
(in the file's samples), or `loop = 0` for no loop. Replacement music pauses
with the game.

The Game Boy has four sound channels shared by music and effects. While a
replacement song plays, the original music is silenced on every channel the
game is not using for an effect, so the game's own effects keep playing. A
replaced effect silences the channels the original effect uses.

## Notes

- Mods only change what you see and hear; the game itself runs exactly the
  same (verified with the project's state-hash tests).
- Large scales need a GPU-accelerated renderer for full speed. The window is
  drawn at the scale it needs, and screenshots use the pack's full scale.
- `tools/make_test_pack.py` builds a synthetic pack from a dump for testing
  (its output contains the game's graphics: keep it local).
